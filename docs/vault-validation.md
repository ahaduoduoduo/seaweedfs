# Vault 本地场景验证

日期：2026-10-15。环境：macOS arm64，真实 `weed vault` 和 OpenList 网关进程，115 边界使用磁盘模拟器。NAS 生产服务和真实 115 没有参与测试。

## 数据与并发

- 基础数据集 243 个对象：60 篇正文及配图、120 张约 2.16 MiB 的 JPEG、约 37.5 MiB 的 MP4、512 MiB 的备份文件，以及 9 MiB 续传文件。
- 3 个业务空间，6 个并发写入客户端。
- Python 范围读取与 Node CLI 完整大文件下载同时运行。
- 2 个浏览器标签页同时读取同一相册块，另一个 CLI 同时读取视频。
- 浏览器额外提交一个正文对象；故障阶段额外提交一个对象，最终共有 245 个当前对象。

## 验证结果

| 场景 | 结果 |
|---|---|
| 上传 4 MiB 后 SIGKILL，重启续传 | 完整摘要一致；启动未访问云目录 |
| JSON 和附件原子提交、旧 revision 并发更新 | 冲突返回 409，其他对象没有部分提交 |
| 关联打包 | 同一笔记正文和配图位于同一 pack |
| 512 MiB 全量下载及跨块范围 | Python 与 JavaScript 独立客户端得到相同明文 |
| 网页上传、正文/图片预览、390px 移动布局 | 浏览器交互通过，无横向溢出 |
| 两标签页共享缓存 | 同一个图片 pack 只触发一次云下载 |
| 浏览器跨域拒绝 | 复用缓存 URL；中转发现过期后自动刷新，客户端完成解密 |
| Vault 与 OpenList 数据库全部删除 | 通过票据和恢复密钥重建，并读取原有正文和大文件范围 |
| 定时检查点与版本 checkpoint 标记 | 自动生成成功，恢复标记对应已完成检查点 |
| 上传失败后进程重启 | 保留本地已提交数据，延迟重试成功 |
| 新申请链接连续返回 403，随后重启 Vault | 账户冷却保持，元数据查询继续正常 |
| 三个业务的缓存 URL 同时下载 | 至少四个传输重叠，不额外申请链接 |
| 五个独立客户端遇到未知有效期链接失效 | 410 和 403 均自动恢复，每轮只新增一次链接申请 |
| 持续返回 410 | 最多两次刷新后返回错误 |
| OpenList 重启后复用 URL | 三个业务新增链接申请为零 |
| 明确有效期的链接过期 | 五个同时请求只触发一次刷新 |
| 旧版单会话数据库升级 | 旧会话可续期，新会话允许并行 |
| 篡改票据签名 | 导入回执和创建目标数据库之前拒绝 |

测试将新链接申请间隔设为 1 秒，并检查相邻申请至少间隔 900 ms；部署默认保持 5 秒。该间隔只约束实际调用提供方的新链接申请。旧 URL 的重复读取及并行下载不受此间隔限制。所有场景要求远端目录查询和凭据泄漏计数为零。

2026-10-15 本地通过 20 项场景：共 245 个当前对象、约 950 MiB 逻辑数据，目录数据库及 WAL 约 4.54 MiB。缓存 URL 的四路传输重叠；五个客户端同时遇到链接失效，每轮只申请一个替换 URL；重启后复用三个业务的 URL，新申请为零。基础数据上传完成后，本地正文和 pack 暂存已清空。精确计数记录在运行报告中。

## 零散收藏与手动同步

`test/vault/sparse.py` 使用默认 `seal_seconds=0`，通过真实服务进程验证：

- 一个业务的一张照片持续暂存，不阻止另一个业务的满包上传。
- 32 个独立笔记分组（每组正文加 2 MiB 附件）共享大包，正文与附件保持同块；不足部分继续暂存。
- 将提交时间设为一天前后重启，确认既有数据库自动升级，内容仍然可读且没有按时间上传。
- 70 MiB 文件先上传约 60 MiB，未满尾部保留；手动同步及进程终止后恢复没有重复上传已经确认的满包。
- 自动检查点不封存未满部分；本地新版本尚未上传时，恢复得到之前的完整云端版本。无变化时不反复上传检查点。
- CLI `sync` 只同步指定业务；只读令牌无法触发同步；浏览器提交与“立即同步至云端”操作分别验证。

容量模式下，包通常接近上限；为保持一个关联批次完整，也可能提前结束一个包。原有 20 项场景显式设置短封存时间以加快故障验证，默认容量行为由此独立场景覆盖。精确结果保存在 `sparse-report.json`。

自动化入口为 `test/vault/scenarios.py` 和 `test/vault/sparse.py`。每次运行的精确计数、新链接申请与下载时间序列和截图保存在 `build/vault-test-results/`；GitHub 的 `vault-scenario-results` 构建附件保存 Linux x86 的对应结果。失败场景是实际服务进程的错误注入，未替代真实服务实现。
